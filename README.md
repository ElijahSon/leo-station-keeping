# Generated C Code: DSAS Validation Model

The folder namded `simulik_DSAS_validation_ert_rtw` contains the C source generated by MATLAB Embedded Coder from the Simulink model `simulik_DSAS_validation.slx`, the validation model of the LEO station-keeping project. It is the implementation output of a model-based design to code workflow: the controller and plant are designed and validated in Simulink, then production C is generated directly from the validated model instead of being hand-written.

## Generation details

| Property | Value |
|----------|-------|
| Source model | `simulik_DSAS_validation` (version 2.0) |
| Toolchain | Simulink Coder / Embedded Coder 24.1 (R2024a) |
| Target | `ert.tlc` (Embedded Real-Time) |
| Hardware target | Intel x86-64 (Windows64) |
| Language | C |
| Generated on | 25 June 2026 |

## Code interface

The generated code follows the standard Embedded Coder entry-point model. The application calls three functions:

```c
void simulik_DSAS_validation_initialize(void);  /* set up states and data */
void simulik_DSAS_validation_step(void);        /* one execution step      */
void simulik_DSAS_validation_terminate(void);   /* shutdown                */
```

A reference harness in `ert_main.c` shows the intended call sequence: initialize once, call the step function in a loop while no error is flagged, then terminate. The model integrates continuous states (the satellite dynamics and the controller), so the step function advances the solver one sample at a time.

## Software-in-the-loop (SIL) verification

The `sil/` subfolder holds a software-in-the-loop verification harness generated alongside the code. SIL compiles the generated C on the host and runs it under the control of Simulink, exchanging data with the model so the generated code can be exercised against the same inputs as the source model.

The harness includes the SIL main (`sil_main.c`), the external interface layer (`xil_interface.c`), and the rtiostream TCP/IP transport that carries data between Simulink and the compiled code. A host executable built from these is also present.

## A note on the other files

Most of the remaining files are toolchain and build output rather than source you would read or edit: object files (`.obj`), the static library (`.lib`), the host executable (`.exe`), makefiles and response files (`.mk`, `.rsp`, `.bat`), and Coder metadata (`.mat`, `.dmr`, manifest). They are produced by the build and are reproducible by regenerating from the model. The `coderassumptions/` folder holds the hardware and arithmetic assumptions Coder verified for the target.

## Regenerating

This code is generated, not hand-maintained. To reproduce it, open `simulik_DSAS_validation.slx` in MATLAB R2024a or later and build the model with Embedded Coder (target `ert.tlc`). Editing the model and rebuilding is the correct way to change the code; manual edits to these files would be overwritten on the next build.
